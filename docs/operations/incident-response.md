# 事件响应手册（Incident Response）

> 版本：v1.0

## 事件分级

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| P0 | 大规模数据泄露/越权/禁止字段入库/恶意更新 | 跨组织越权访问、禁止字段进入服务端或模型、未签名更新被利用 |
| P1 | 采集链路大面积故障/自启动失效 | 登录后无心跳、进程反复崩溃、上传长时间中断 |
| P2 | 局部功能问题 | 单设备捕获率下降、分类错误、AI 事实错误 |

## P0 响应流程（SLO：立即响应）

1. **阻断**：立即阻断相关访问（吊销设备/用户令牌）、停止模型调用、策略回滚、版本阻断。
2. **保留证据**：只读复制日志与元数据，不写入、不删除；禁止字段命中触发安全告警，
   但告警本身不得记录原始敏感值。
3. **评估影响**：确认受影响范围（组织/设备/时间段/数据类别）。
4. **修复**：根因修复 → 回归测试 → 全量发布门禁。
5. **清理**：对进入服务端/模型的禁止字段按保留与清理流程处置，写删除证明。
6. **复盘**：5W 分析、改进项、更新威胁模型。

## P1 响应流程

1. 监控端告警（Agent 在线率、健康样本、队列深度）。
2. 确认影响面（设备数、时长）。
3. 有界恢复：重启、自启动修复、权限引导重新完成。
4. 缺口标记：受影响时段在分析中标记为缺口，不当作低使用。
5. 复盘与修复。

## 备份与恢复

- PostgreSQL 每日全备 + 持续日志/PITR（正式环境；Phase 1 本地开发可简化）。
- 备份加密、单独权限、每季度恢复演练（恢复后重放保留/清理台账）。
- 没有真实恢复演练证据前，只能标记 `planned`，不能声称可恢复。
- 明确保留期在备份中的最终过期时间。

## 联系与记录

- 事件记录写入 `docs/operations/incidents/`（含时间线、处置、复盘）。
- 所有处置动作写审计日志。
