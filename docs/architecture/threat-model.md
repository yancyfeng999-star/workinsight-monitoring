# 威胁模型（Threat Model）

> 版本：v1.0 · Phase 1 版本（正式版在 Phase 4 前完成全面演练）

## 信任边界

1. 窗口标题、页面标题是不可信输入（可能含个人信息、恶意 prompt、超长文本）。
2. 浏览器扩展只能通过白名单 Native Messaging Host 与 Agent 通信，不能访问监控端 API。
3. Agent 只能使用设备级凭据上传本公司登记设备的事件，不能查询监控端数据。
4. 服务端接收层不信任 Agent 时间、版本、序号、字段长度；必须校验、限流、幂等。
5. LLM（DeepSeek）是半可信处理方，只得到脱敏聚合输入；输出必须做 Schema、事实和政策校验。
6. 管理员是潜在滥用角色；个人明细访问、导出、策略修改和删除必须审计。
7. Agent 与扩展是纯采集面；协议和 CI 必须阻止 Prompt/凭据/模型权重/评分规则下发到 Agent。

## 威胁登记

| 威胁/滥用 | 后果 | 必须控制 |
| --- | --- | --- |
| Agent 未按清单安装 | 覆盖缺口、数据误读 | 设备清单、安装状态、版本、心跳对账 |
| 恶意管理员查看个人细节 | 内部数据滥用 | 最小 RBAC、个人详情单独 Scope、理由字段、审计与复核 |
| Agent 凭据被复制 | 伪造设备/注入数据 | 设备非对称密钥、Keychain/DPAPI、挑战签名、吊销与轮换（Phase 2） |
| 上传重放/重复 | 统计错误 | sequence/event id/批次幂等、时间窗和签名 |
| 本地数据库泄露 | 暴露行为轨迹 | 先过滤、短保留、应用层加密、系统密钥库、文件权限 |
| 跨组织/部门越权 | 大规模泄露 | 每层 org/team scope、集成测试、管理员与运维分权 |
| 标题/URL 泄露敏感信息 | 医疗/金融/身份暴露 | domain-only、query 永不保留、本地屏蔽、加密列、短保留 |
| LLM Provider 泄露/留存 | 公司数据或凭据泄露 | 只发必要汇总、密钥隔离、禁发字段测试 |
| Prompt Injection | 错误/越权结论 | 无工具模型、结构化数据边界、输出事实/政策校验 |
| 供应链/恶意更新 | 控制全部终端 | 锁版本、SBOM、依赖扫描、签名包、签名更新、灰度阻断 |
| Agent 失效/被退出 | 数据不完整被误判 | 健康状态、缺口标记、完整度报告 |
| 自启动关闭/崩溃循环 | 长时间漏采 | 自启动状态上报、有界重启、熔断、告警 |
| 分析逻辑误入 Agent | 密钥泄露、版本不可控 | 依赖扫描、产物扫描、契约测试 |
| 清理不彻底 | 存储膨胀、旧数据再现 | 数据地图、级联清理、备份过期策略 |

## 硬性安全边界（不可协商）

- Agent 不提供远程 Shell、脚本、文件下载或进程控制 API。
- 不伪装系统进程，不绕过 macOS/Windows 的启动项与权限管理。
- 控制面策略必须签名；Agent 只接受允许字段，不能通过配置开启隐藏能力。
- 策略只能控制采集字段、时段、过滤、上传和诊断；不允许下发 Prompt、模型地址或评分规则。
- 正式更新必须同时验证平台签名与项目更新签名（Phase 4）。
- 模型服务账户不拥有原始活动表全量查询权限（Phase 3）。
- 个人明细导出带水印、过期和审计（Phase 2）。
- 日志不写 URL query、标题明文、Token、私钥或模型完整敏感输入。
- 安全事件开关：设备吊销、模型 Provider 停用、策略回滚、版本阻断。
