# 回滚运行手册（Rollback Runbook）

> 版本：v1.0

## 回滚目标

- Agent 版本回滚（macOS/Windows）；
- 采集策略回滚（服务端策略版本）；
- 分类规则/分类词典回滚；
- Prompt 版本回滚；
- 模型 Provider 切换/停用；
- 数据库迁移回滚（迁移必须可逆或前向兼容）。

## 触发条件

- 数据完整率异常下降（Pilot 指标连续 2 天不达标）；
- 禁止字段进入服务端（P0，立即阻断+清理，不回滚即可处理的先阻断）；
- 权限体验崩溃循环或资源超标（CPU/内存目标不达标且无法快速定位）；
- AI 报告事实错误率超标（> 2%）；
- 新版本发现高危漏洞或行为异常。

## 回滚流程

1. **决策**：发布负责人确认回滚类型与影响面；写审计记录。
2. **策略回滚**：服务端发布旧策略版本（带版本号与冷却时间），Agent 下个心跳拉取；
   不回滚的客户端 24h 后强制重试。
3. **Agent 回滚**：Phase 4 前手动卸载安装旧包；正式版通过更新通道回滚（签名校验必须保留）。
4. **分类/Prompt 回滚**：Worker 作业使用版本化配置，切回上一稳定版本并重新生成当日数据。
5. **模型停用**：关闭 Provider；系统自动降级为规则报告，采集与统计不受影响。
6. **数据库迁移回滚**：前向兼容迁移（先加列后删列）；异常时按备份恢复（见 incident-response）。

## 冷却与灰度

- 策略修改有冷却期（建议 5 分钟最小间隔）；发布有灰度（5 台 → 20–50 台）。
- 问题版本阻断：版本清单标记 `blocked`，Agent 不安装不更新。

## 完成后

- 验证：健康心跳恢复、捕获率恢复、数据完整率恢复；
- 复盘：根因分析、修复项、回归测试；
- 更新发布状态机记录（回滚后的状态不能跳过验证）。
